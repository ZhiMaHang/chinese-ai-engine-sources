# 中文 AI 引擎信源实验室 · chinese-ai-engine-sources

我们每周拿同一套中文题去问一批 AI 引擎，记录**它们回答时引用了哪些网站**，
然后把这份信源数据原样公开。

这个仓里有三样东西：

| 目录 | 内容 |
|---|---|
| `prompts/` | 实际在跑的 **45 道中文 GEO 监测题**，分五层 |
| `data/` | 每期的**引用池快照**：被引域名及次数 |
| `scripts/` | 处理引用数据的脚本，含一个专门用来避免误判的工具 |

## 三条读数提醒（都是我们自己踩过的）

### 1. 域名进了引用池 ≠ 你的文章进了引用池

这是最容易读错的一条，我们判错过一次。

看到某技术社区域名被引 89 次，很自然会想「其中有多少是我们的」。
当时用了一个看起来合理的路径通配去标记「我方文章」，得出 22 次——
换成用真实文章 ID 逐个精确匹配后，实际是 **0 次**。那 89 次全是别人的内容。

**判断自己的内容有没有被引，必须落到 URL / ID 级精确匹配。**
`scripts/domain_vs_article.py` 就是为这件事写的，并且会拒绝用域名当资产标识。

### 2. 加题会机械拉低命中率

命中率的分母是「题数 × 引擎数」。加了题，即使命中数一字不变，比率也会掉。
**跨期比较必须用同题面子集**，否则会把「加了题」读成「效果下降」。

### 3. 首窗读数不能当基线

我们有一层题在某一期是「4 道命中 3 道」，下一期同样 4 道**命中 0**。
一个观察窗给出的数字，方向都可能是反的。**至少要第三个点才谈得上水位。**

## 数据口径

- **这是单一商户题集的实测，不是行业均值。** 题目围绕 GEO / AI 可见度这一个品类，
  换品类结论多半不一样。
- 引用数是 **URL 出现次数**；同一 URL 在不同题、不同引擎下重复出现会重复计数。
- 每期实际跑满的引擎数会标在 `_meta` 里。issue-5 有一个引擎因登录态失效只跑了
  28/45，其读数不进可靠区间——**这类缺口我们照实标，不补齐、不抹平**。
- 从 issue-11 起按月合并：同一 URL 在不同轮次里出现会重复计数，所以月度数的量级约为单轮的 3 倍，
  **不能和单轮期直接比绝对数**。按轮次编号切分，不按日期窗口切分。
- 数字是取数时点的快照（issue-11 为北京时间 2026-09-29 16:08）。监测记录会因补跑被原地改写，
  事后重算可能略有出入；对不上时先对取数时点，再对口径。

## 更新频率

按月更新：每期合并上一期之后、取数时已经收口的全部周监测轮次，取数时还没收口的轮次顺延到下一期。

编号 issue-N 的 N 取本期所含末轮的轮次号，所以编号不连续：issue-5 之后是 issue-11。
第 6~8 轮是 8 月的周监测，没有单独发布；第 9、10 轮已并进 issue-11。

**如果这个仓超过两个月没更新，说明我们没在跑了，请按末期的日期判断数据新鲜度。**
